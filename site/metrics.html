03 · Metrics & North Star

指标体系与北极星

指标体系 = 北极星 + 输入树 + 护栏 + 反向指标：北极星回答"公司为什么存在"， 输入树回答"什么驱动它"，护栏回答"别为拉高它而伤害公司"，反向指标回答"它有没有被弄虚作假"。 以下每个节点都锚定 metrics.yaml 的真实定义——已实现可直接查数，规划给出了定义草案。

关于「规划」标签 本页与业务结构页的【规划】项是生产路线图的显式记录（演示环境不实现、但定义草案已就位）， 不是待修缺陷——把"现在做不了什么"写清楚，与把"做了什么"写清楚同样重要。

1构建方法：原子指标 → 衍生指标 → 计算指标

指标体系不是 31 条平铺的定义，而是一座三层金字塔：原子指标（事实表的裸聚合，不可再拆）→ 衍生指标（原子 + 时间周期 + 修饰词 + 统计粒度——"口径"就住在这一层）→ 计算指标（指标÷指标、指标−指标的复合）。 本项目 31 个注册指标 = 14 原子 + 17 计算，且每条都在 YAML 声明了更细的 metric_type（simple 2 / filtered 11 / cumulative 1 / ratio 15 / derived 2——与 MetricFlow 五类型学对应， 由 check.py 校验"声明与 expr 结构一致"）；每个计算指标都能拆回原子血缘（见第 5、6 节）。

层定义本项目的实现形态数量
原子指标 挂在单张事实表上的裸聚合度量：计数 / 去重计数 / 求和 / 中位数——不可再拆，是全部上层指标的分子分母来源 count(*) FILTER (WHERE success)、sum(amount) FILTER (WHERE NOT refund)、count(DISTINCT user_id)…（FILTER 是修饰词，不改变原子性） 14
衍生指标
（口径层）		 原子指标 + 时间周期（1d/7d/14d/滚动）+ 修饰词（业务限定：非退款/成功/首触/线性/免费发放…）+ 统计粒度（窗口单值/逐日/滚动去重） metrics.yaml 的 spec 就是衍生层的显式声明：default_time=周期、expr 的 FILTER=修饰词、grain/series_grain/rolling_distinct_on=粒度。 同一度量换周期即新衍生指标（daily vs weekly_successful_creations） 31 (全部)
计算指标 由两个及以上衍生指标经运算复合：比率（÷）、差值（−）、占比（×100）——必须声明可加性与分母保护 受限于自研引擎不支持指标间引用（见语义层·能力边界），计算指标目前以"双聚合写进单条 expr"实现（如 arppu = sum÷count 同窗同表）；生产用 MetricFlow derived/ratio metric 17
两条铁律（从事故里来的） ① 计算指标的分子分母必须同窗同口径——毛利率分子分母若一个 7d 一个 14d，算出来的数没有任何业务含义； ② 比率分母一律 nullif(·,0) / greatest(·,1)——分母为 0 时出 null 而不是 inf（inf 会被写成非法 JSON，前端整页抛错）。

3为什么是「人」不是「次数/分钟」：机制论证

计量单位与成本单位不同构
  • 次数把 2 秒与 12 秒同记为 1（实测平均 7.0 秒/次，恰为生成时长分布的算术结果）
  • 分钟数直接挂钩 API 成本——把它当北极星，等于让"成本"最大化
计数器可被撑起，「人」不会
  • 重度用户与赠送额度能把次数/分钟撑起，创作者数不能
  • 护栏数据佐证：Veo 3.1 成功率 96.7% 全场最高、创作占比仅 5.4%、毛利 −125.6%——次数上升可与毛利下降同时发生

6指标关系：四条计算链（谁是谁的分子分母）

计算指标的血缘不是文档修辞——改一个原子口径，下游整条链的数字都要重算。 下图按业务问题分四条链，箭头即"分子/分母来源"：跨数据域的计算指标（cac、roas）是烟囱式系统最容易算错的地方，因为分子分母在两张不同的烟囱表里。

蓝底=计算指标，白底=原子指标。文字版血缘：毛利链 = 现金(非退款 sum) → 按当日积分消耗占比分摊到模型 → (分摊收入 − 成本秒数×单价) ÷ 分摊收入；该链任何一环改口径（退款处理、分摊规则、单价表），三个毛利指标同时变—— 这就是"口径变更必须升 version 且评估下游"的原因。

8证据与边界：同向，但不线性

相邻两日对比：__PAIR1_FROM__→__PAIR1_TO__ 创作数 +8.1% 而收入 +84.3%，弹性 10.4； 另一组相邻日（__PAIR2_FROM__→__PAIR2_TO__，+15.9% vs +32.9%）弹性约 2.06 —— 两组同为"同向"，弹性却差约 5 倍。

结论：只能说「创作与收入同向」，不能说线性、不能互相折算。 证据窗口 __WIN_START_FULL__ ~ __WIN_END__，日期对绑定日序列可精确复算（evidence.py，偏差 >5% 即 FAIL）。 以上均为演示数据上的机制推演 / 可复现复算，不是对任何真实公司的实证。

通则：比率 > 100% 几乎总是口径/边界警报 语义层工程指南的实测案例：跨月退款按各自时间锚点对齐后，边界月份会出现"退款率 105.3%"的残缺桶（分子含上月下单、分母只含本月）。 本项目的付费燃烧率 125.6% 与之同构而根因不同——它是分子混入了免费消耗（台账无资金来源）。 现象一样、病根两样，但处置相同：比率超 100% 必须停下来查口径，而不是截个图发群里。该已知现象已锁进黄金查询 G10。
