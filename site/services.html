04 · Data Services

数据服务场景

指标的价值在被决策使用的那一刻才成立。本章把口径翻译成六个真实决策场景—— 每个场景都走完「决策问题 → 核心指标 → 口径陷阱 → 动作」四步； 口径陷阱一列是它们存在的理由：跳过这一列，场景就会回到烟囱式猜数。

1六个决策场景

① 模型流量分配已实现
  • 问题：默认模型给谁？哪家该降流量/下架？
  • 指标：model_gross_margin · model_success_rate · weekly_minutes_generated
  • 陷阱：收入必须按积分占比分摊到模型——旧口径把白送额度燃烧记成收入，毛利 33.1% vs 现金 12.9%
  • 动作：Veo 3.1 毛利 −125.6% → 限流为旗舰选项不给默认流量
② 渠道预算分配已实现
  • 问题：下季度预算在 SEO/红人/付费/联盟间怎么分？
  • 指标：cac · roas · channel_revenue_first_touch / linear · active_creators 按渠道拆
  • 陷阱：双口径并存——首触看获客质量、线性看助攻价值；当前数据下线性不可用于预算决策（40% 收入无归属）
  • 动作：按「首触收入 + 该渠道周活跃创作者」双列决策，见看板渠道表
③ 激活路径优化已实现
  • 问题：新用户为什么流失？首次成功卡在哪？
  • 指标：activation_1d/7d · ttfc_median · first_day_creations · retention_d1
  • 陷阱：「次日」必须是注册次日当天有活动——无界滚动口径把 48.1% 报成 84.2%；队列末点未成熟要标注
  • 动作：ttfc 分钟中位数定位引导流失点；漏斗第一跳（会话）缺数据 → 埋点需求单
④ 成本异常监控已实现
  • 问题：成本结构有没有往最贵档漂移？
  • 指标：high_cost_exposure（现值 13.1%）· company_gross_margin
  • 陷阱：$0.03/秒 是经验阈值不是平衡点——现金平衡点 $0.0217/秒，Kling/Runway 已负毛利却不在分子；阈值声明与指标名必须诚实
  • 动作：规划 改动态 break_even = 窗口收入/成功秒数
⑤ 续费健康度已实现
  • 问题：付费用户下个月还在吗？北极星涨是不是白嫖撑的？
  • 指标：payer_retention_wow（现值 13.5%，单期快照）· balance_capped_revenue_gap（$1,535.2）
  • 陷阱：分子必须是「两周都付费」的用户——误写成"本周所有付费用户"，增长期比率会 >100%，护栏把坏消息吃掉
  • 动作：北极星涨 + 续费不动 → 触发证伪条件 R2 观测
⑥ 实时任务口径演示级
  • 问题：任务监控上实时大屏，流式数字和离线对不上怎么办？
  • 指标：批精确 vs watermark vs 纯到达序 三口径
  • 陷阱：watermark 会丢迟到数据（显式侧输出可审计）；到达序不丢但错窗（无任何报警）——两种病药方不同
  • 动作：流批对账——守恒断言作为上线验收方法

2治理落位 Ⅲ：八道门禁 = 发布前的监控

监控不是上线后才想起来的一张大盘——门禁不过是把告警前移到发布前。 每道 CI 门禁都对应一类生产监控的对应物（golden.py 是第八道：语义层的验收测试，形态参考 golden_queries.yml——业务问题→查询→断言）：

CI 步骤（顺序执行）门禁职责生产监控对应物
build.py --fresh（内含 dbt build）__DBT_TEST_COUNT__ 项 dbt 节点（模型 + 行级测试 + 守恒断言），不过则构建失败ETL 任务的数据质量卡点/告警
check.py --data口径契约 / 前端×产物契约 / 跨文件一致 / 数据侧失真数据质量巡检（DQC 规则集）
evidence.py页面每个数字可从产物复算（弹性按日期对、流批守恒）报表数字稽核（BI 数 vs 明细数）
golden.py14 条黄金查询回归：已知值（4,278/48.1%/12.9%…）/ 守恒（首触合计=现金）/ 行为断言（非法维度、未注册窗口必须报错）口径变更回归测试（改 YAML 后哪些数字变了，一眼可见）
northstar_eval.py判据预注册 + 三候选弹性落盘指标有效性复盘（防事后择优）
js_syntax_probe.py模板字面量/括号配对（无 Node 查白屏）前端可用性哨兵
compare_out.py占位符按源预渲染后逐文件比对，防"自证同步"发版物 vs 源一致性巡检
verify_served.py --dir断言发布页关键事实真的渲染线上拨测 / 端到端验收
生产监控四件套（规划） 数据可观测性五支柱中，lineage 本项目已有（dbt docs）；其余四件按此规划： freshness（各表 SLA 延迟告警）· volume（行数日环比异常）· schema drift（列增删/类型变更）· distribution（空值率/均值漂移——check.py 的空日与 ttfc 退化检查已是其雏形）。
